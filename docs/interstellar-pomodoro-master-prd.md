# 星际跃迁番茄钟 iOS App - 大师级 PRD 开发执行版

**日期**: 2026-05-15  
**文档状态**: 大师级候选稿，可进入 MVP 开发前评审  
**适用团队**: 产品、iOS、设计、测试、增长  
**一句话**: 把难熬的专注时间，变成一场低功耗、系统级、可留下纪念物的静默星际跃迁。

## 1. 产品判断

### 1.1 真实用户任务

用户不是缺一个倒计时器，而是缺一个能让 25 分钟不那么焦虑、不那么枯燥、并且愿意反复启动的低负担专注仪式。

核心 JTBD:

- 当我准备学习、写作、复习或深度工作时，我想不用打开复杂 App 就能立刻进入一段专注。
- 当时间流逝时，我不想被倒计时数字持续压迫，而想知道系统正在稳定陪伴我。
- 当我完成后，我希望留下一个好看、克制、可保存或分享的成果证明。

### 1.2 北极星指标

**7 日内完成 3 次以上 25 分钟专注的用户占比。**

辅助指标:

- 首次启动成功率: 用户第一次进入后 60 秒内能启动一段专注。
- 完成率: 启动后的标准专注完成率。
- 纪念物保存率: 完成后保存或分享黑石碑卡片的比例。
- D7 留存: 第 7 天仍启动专注的用户比例。

### 1.3 产品定位

这不是普通番茄钟，也不是重度科幻游戏。它是 iOS 18 系统能力上的轻量时间仪式:

- 启动入口在系统层: 控制中心、锁屏、灵动岛、Widget。
- 运行体验低干扰: 不用盯着 App，不用看跳动数字。
- 完成后有资产: 把专注时长变成星际里程、坐标和黑石碑卡片。
- 所有核心数据本地优先: 不依赖账号、云端或后端。

## 2. 市场与替代方案

| 替代方案 | 用户为什么会用 | 缺口 | 本产品赢法 |
| --- | --- | --- | --- |
| 系统时钟/计时器 | 可靠、免费、系统内置 | 只有倒计时，没有仪式感和长期资产 | 同样低负担，但完成后有精神资产和视觉奖励 |
| Apple Focus/专注模式 | 能减少打扰 | 不解决专注启动和完成反馈 | 作为专注模式的轻入口与完成记录层 |
| Forest 类专注 App | 有成长/游戏化反馈 | 需要进入 App，视觉和社交机制容易变重 | 系统级轻启动、低功耗、无重社交压力 |
| 待办/习惯 App | 能规划任务 | 不负责一段时间内的状态陪伴 | 只聚焦一次 25 分钟跃迁，不承担任务管理 |

商业方向先不急着复杂化。MVP 不上订阅墙，先验证留存和保存率。后续可测试:

- 高级视觉包和黑石碑模板。
- 长周期星图主题包。
- 一次性买断的纪念物导出包。
- 与 Shortcuts / Focus Filter 的高级联动。

## 3. 首版边界

### 3.1 P0 必须做

1. **快速启动专注**
   - 支持 App 内启动 25 分钟专注。
   - Spike iOS 18 Controls / Widget / App Intent 能否作为系统级启动入口。
   - 如果系统入口受限，P0 仍必须保证 App 首屏一键启动。

2. **低干扰运行态**
   - 运行中显示极简进度，不显示巨大倒计时数字。
   - 支持 Live Activity / Dynamic Island 的可行性 Spike。
   - App 被切后台后，计时以 `startAt + duration` 推导，不依赖前台持续计时。

3. **完成纪念物**
   - 完成后生成一张黑石碑风格卡片。
   - 卡片包含时长、星际坐标、Session 编号、日期。
   - 支持保存到相册或系统分享。

4. **本地记录**
   - 保存每次 Session 的开始、结束、完成状态、中断次数、生成坐标。
   - 首页展示累计专注、连续完成、最近纪念物。

5. **放弃阻力**
   - 运行中停止必须二次确认。
   - 文案克制，不羞辱用户，只提示会丢失本次跃迁纪念物。

### 3.2 P1 可以做

- 桌面 Widget 展示最近星际里程。
- Focus Mode / Shortcuts 联动。
- 多个专注时长模板。
- 星图收藏页。
- 纪念物模板收藏。

### 3.3 P2 暂缓

- 多人舰队、排行榜、社交广场。
- 复杂 3D 宇宙探索。
- AI 专注力分析。
- 云同步、账号系统、订阅系统。
- 白噪音播放器。

## 4. 用户旅程

### 4.1 首次进入

1. 用户看到一句话定位和一个主按钮: “开始 25 分钟跃迁”。
2. 下方显示三个承诺: 静默、低功耗、完成后生成黑石碑。
3. 用户无需注册、无需配置，即可启动。
4. 首次启动前只询问必要权限。MVP 默认不请求定位、相机、通讯录。

### 4.2 专注运行

1. 用户点击开始。
2. 系统记录 `startAt`、`duration`、`sessionId`。
3. UI 进入低亮度深空状态，仅显示进度光尺和一句状态文案。
4. 如果切后台，返回时按真实时间重新计算剩余时间。
5. 如果用户停止，弹出确认: “终止后不会生成本次黑石碑”。

### 4.3 完成后

1. 系统自动生成 Session 结果。
2. 展示黑石碑卡片和本次星际坐标。
3. 用户可保存、分享、回到首页。
4. 首页星图点亮一个小节点。

## 5. 页面与组件

### 5.1 首页 Dashboard

目标: 一眼知道现在能做什么，以及过去留下了什么。

组件:

- 主启动按钮: 开始 25 分钟跃迁。
- 累计数据: 总专注时长、完成次数、连续天数。
- 最近黑石碑: 最近一次完成纪念物。
- 星图进度: 用 Bento Grid 呈现累计里程。

状态:

- 空态: 尚未完成跃迁，显示第一步。
- 运行中: 进入运行页，不在首页堆信息。
- 完成态: 显示最新黑石碑。
- 失败态: 本地数据读取失败时保留启动入口，并提示可重试。

### 5.2 运行页 Focus Run

目标: 陪伴，不打扰。

组件:

- 深空背景。
- 极细进度光尺。
- 状态文案: “静默跃迁中”。
- 停止按钮: 低优先级，二次确认。

验收:

- 运行页 25 分钟内不能持续高频动画。
- 低电量模式下关闭非必要视觉效果。
- Dynamic Type 不应导致按钮遮挡。

### 5.3 完成页 Relic

目标: 给用户一个愿意保存的完成证明。

组件:

- 黑石碑卡片预览。
- 保存按钮。
- 分享按钮。
- 本次摘要: 时长、坐标、Session 编号。

黑石碑视觉:

- 背景: 接近纯黑，但保留轻微材质。
- 主信息: 完成时长，占卡片视觉主体。
- 辅信息: 坐标、Session、日期。
- 边框: 极细 Quantum Glass 高光，不使用复杂实时折射。

## 6. 技术方案

### 6.1 技术栈

- iOS: SwiftUI
- 数据: SwiftData
- 系统集成: App Intents、WidgetKit、ActivityKit、UserNotifications
- 分享图生成: SwiftUI `ImageRenderer`
- 日志: `Logger`
- 测试: XCTest、XCUITest、Metrics

### 6.2 数据模型

```swift
@Model
final class FocusSession {
    var id: UUID
    var startedAt: Date
    var plannedDuration: TimeInterval
    var completedAt: Date?
    var cancelledAt: Date?
    var interruptionCount: Int
    var coordinateCode: String
    var relicImagePath: String?
    var createdAt: Date
}
```

```swift
@Model
final class UserProgress {
    var id: UUID
    var totalCompletedSeconds: TimeInterval
    var completedSessionCount: Int
    var currentStreakDays: Int
    var lastCompletedAt: Date?
}
```

### 6.3 状态流

```text
idle -> running -> completed -> relicGenerated -> archived
idle -> running -> cancelling -> cancelled
running -> appBackgrounded -> running
running -> appTerminated -> recoveredFromStoredStartAt
```

计时原则:

- 不依赖每秒 tick 作为事实来源。
- 事实来源是 `startedAt` 和 `plannedDuration`。
- UI 只是派生状态。
- App 重启后按本地记录恢复。

### 6.4 系统能力 Spike

开发第一天必须验证:

- iOS 18 Controls / App Intent 是否能无障碍启动 Session。
- Live Activity 是否适合展示极简进度。
- ImageRenderer 生成黑石碑是否在 1 秒内完成。
- 低电量模式下视觉降级策略是否可控。

## 7. 视觉标准

视觉关键词: 深空、低功耗、仪器感、纪念物、克制高级。

颜色:

- Deep Space: `#05070B`
- Signal Green: `#A3B18A`
- Glass Edge: `#DDE8FF`
- Text Primary: `#F8FAFC`
- Text Muted: `#94A3B8`

排版:

- 系统字体优先。
- 运行页字号克制。
- 黑石碑主时长必须足够大，截图中 1 秒读懂。

动效:

- 启动瞬间允许 200ms 以下的轻微响应。
- 运行中不做粒子、3D、持续高亮。
- 完成页允许一次性生成与出现动画。

## 8. 验收标准

### 8.1 产品验收

- 新用户 60 秒内能启动第一段专注。
- 运行中用户不需要理解任何科幻概念。
- 完成后 80% 测试用户能理解黑石碑代表一次专注完成。

### 8.2 工程验收

- Session 在 App 切后台后仍能按真实时间恢复。
- App 被强杀后重新打开能恢复或结算未完成 Session。
- 本地数据无网络也可完整使用。
- 生成分享图不阻塞主线程超过可感知阈值。

### 8.3 性能验收

- 运行态 CPU 持续占用保持极低。
- 不使用持续 GPU 渲染作为核心体验。
- 低电量模式下自动关闭非必要视觉。
- 25 分钟运行不能导致明显发热。

### 8.4 可访问性验收

- VoiceOver 能读出当前状态、剩余大致进度、停止按钮。
- Dynamic Type 下主按钮和关键状态不溢出。
- 颜色对比满足可读性。
- 停止确认不能只依赖颜色表达危险。

## 9. 开发任务拆解

### Sprint 0: Spike

1. 验证 App Intent / Controls 启动路径。
2. 验证 Live Activity 极简进度可行性。
3. 验证 SwiftData Session 恢复。
4. 验证黑石碑图片生成。

### Sprint 1: MVP 骨架

1. 搭建首页、运行页、完成页。
2. 实现 `FocusSession` 和 `UserProgress`。
3. 实现 App 内一键启动、停止确认、完成结算。
4. 实现黑石碑预览和保存。

### Sprint 2: 系统集成

1. 接入 Widget / Controls 可行路径。
2. 接入 Live Activity。
3. 增加低电量降级。
4. 增加日志与基础 Metrics。

### Sprint 3: 体验打磨

1. 视觉定稿。
2. 5-8 人可用性测试。
3. 根据 D0 反馈修首屏、停止确认、完成页。
4. 准备 TestFlight。

## 10. 风险与裁决

| 风险 | 等级 | 裁决 |
| --- | --- | --- |
| iOS 18 Controls 能力不满足想象 | 高 | Sprint 0 必须先验；若失败，P0 保留 App 内一键启动 |
| 科幻概念过重 | 高 | 首屏不解释“相对论/引力舱”，只说“开始 25 分钟跃迁” |
| 视觉导致功耗过高 | 高 | 运行态禁止持续复杂动效 |
| 黑石碑审美不够高级 | 中 | 设计先出 3 套静态模板，再开发 |
| 用户完成后不愿分享 | 中 | 不把分享作为唯一留存，星图和本地记录也必须成立 |
| 放弃确认太重 | 中 | 只在运行中停止时增加摩擦，不影响启动 |

## 11. 不做清单

- 不做账号系统。
- 不做云同步。
- 不做排行榜。
- 不做多人舰队。
- 不做 AI 分析。
- 不做重度 3D。
- 不做白噪音。
- 不做复杂任务管理。

## 12. 最终开工结论

这份 PRD 可以作为 MVP 开工基准。团队第一优先级不是做炫酷宇宙，而是证明一个判断:

**系统级低负担启动 + 低压迫运行 + 完成纪念物，能否让用户比普通倒计时更愿意重复完成专注。**

只要这个判断成立，后续视觉包、星图资产、系统联动和商业化才有意义。否则所有科幻叙事都只是装饰。
