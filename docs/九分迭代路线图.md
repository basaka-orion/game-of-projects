# 九分迭代路线图

目标：把 BASAKA / 项目的游戏从“能力很多的本地应用”推进到 9.0-9.5 分的个人外脑 OS。

评分口径不是视觉好看，而是这条主循环是否稳定成立：

> 捕获输入 -> 理解 Boss 与项目 -> 归档记忆 -> 编译知识 -> 推演行动 -> Agent 执行 -> 复盘学习。

## 当前基线

| 维度            | 当前估分 | 9 分标准                                                      |
| --------------- | -------: | ------------------------------------------------------------- |
| 愿景贴合        |      7.5 | 用户能明确看到 Boss、项目、记忆、知识、推演、自动化是一条闭环 |
| 架构厚度        |      8.0 | 能力模块厚，同时边界清晰、数据契约稳定、验证可跑              |
| 产品闭环        |      6.0 | 每个输入都有去处，每个输出能沉淀、复用、复盘                  |
| 信息架构        |      5.5 | 沙盘是唯一总控台，副官是日常入口，次级功能不挤顶栏            |
| 知识/记忆       |      7.0 | 来源、证据、去重、召回、归档状态都可追踪                      |
| Agent 复用      |      6.5 | 所有 Agent 拿到同一份 Boss/知识/项目上下文，并回写结果        |
| 稳定性/工程体验 |      4.5 | git、typecheck、build、smoke、数据备份都可重复运行            |

## Iteration 1: 工程地基恢复

目标评分提升：稳定性/工程体验 4.5 -> 6.5。

交付：

- 增加 `npm run health:check`，检查 dataless 文件、git 可读性、工具 shim 权限。
- 增加 `npm run health:hydrate`，请求 macOS File Provider/iCloud 把关键工程文件下载到本地。
- 增加 `npm run verify`，在健康检查通过后执行 typecheck 与 build。
- 明确阻塞：当前大量关键文件在 File Provider/iCloud 下是 `compressed,dataless`，全量验证不可依赖。
- 通过后才能进入大范围沙盘改造。

验收：

- `npm run health:check` 通过。
- 如遇 dataless 阻塞，先运行 `npm run health:hydrate`，再复跑 `npm run health:check`。
- `git status --short` 可运行。
- `npm run typecheck` 至少能启动并给出真实 TypeScript 诊断。

当前执行结果：

- `npm run health:check` 已可稳定运行。
- `npm run health:hydrate` 已加入；它默认只请求关键工程文件，不改写源码内容。
- 工具 shim 已修复，Prettier / esbuild / tsc / vite / vitest 的入口可执行。
- 关键工程文件已经本地可读，`git status --short` 可运行。
- 健康检查已扩展到关键运行时依赖入口：`better-sqlite3`、`redux`、`scheduler`、`zod`。
- 已修复半包依赖：`better-sqlite3` 缺 `lib/index.js`、`redux` 缺 `dist/redux.mjs`。
- `npm run verify` 已通过：health check、`tsc --noEmit`、生产构建全部完成。
- 当前剩余风险：构建仍提示主包超过 500 kB、多个动态导入无效；这不是阻塞，但会进入性能拆包/体验 polish 阶段。

- 顶部只保留核心入口；所有复杂功能放入沙盘内部。
- 每个模块显示状态、最近输入、未处理事项、下一步建议。

验收：

- 用户从首页 5 秒内知道系统当前“知道什么、缺什么、该做什么”。
- 启蒙/画像/推演室都能从沙盘进入，并保留当前业务状态。

当前执行结果：

- Openbasaka 顶栏已收敛为 `BASAKA / 角色 / 历史 / 沙盘 / 收起`。
- `启蒙收件箱`、`画像工坊`、`推演室` 已从顶栏移入 `沙盘` 弹出菜单，避免顶栏继续横向堆功能。
- 沙盘新增默认 `总控` 页，进入 `#/sandbox` 后优先看到外脑 OS 巡检面板。
- 总控页已按主循环组织：今日入口、最近 Boss 记忆、外脑主循环、项目网络、执行与自动化。
- `启蒙收件箱`、`画像工坊`、`推演室` 在沙盘总控页内有明确入口，并与记忆/知识/Agent/定时任务处在同一张操作图上。
- 已通过 Chrome CDP 视觉 smoke：桌面 1440 视口能看到 `沙盘总控台`；窄窗口也能渲染 `沙盘总控台`，未回到 onboarding。
- 已通过 `npm run verify`。

- 启蒙归档、画像更新、知识 ingest、推演结果都写入同一条事件流。

验收：

- 任意一次对话/归档/推演能追踪到来源和下游影响。
- Agent 使用上下文时能说明用了哪些 Boss/知识/项目证据。

当前执行结果：

- 新增 `src/lib/operating-loop/types.ts`，定义 `InputEvent`、`MemoryCandidate`、`KnowledgeSourceRecord`、`BossSignal`、`ProjectSignal`、`AgentAction`。
- 每类记录已经统一包含 `stage`、`createdAt`、`source`、`confidence`、`entities`、`projectIds` 等主循环字段。
- 新增 `src/lib/operating-loop/deck.ts`，把总控台的入口、主循环、项目网络、执行层配置从 React 组件中抽离。
- `OverviewTab` 已改为消费 `operating-loop` 契约，不再把核心主循环结构硬编码在页面内部。

- `dbSaveConversation`、启蒙候选/归档、`dbSaveMemory`、Boss 画像快照、项目决策、项目突触、知识来源导入都会写入事件账本。
- `assembleContext` 已注入最近主循环事件，Agent 不再只能看零散的 Boss memory / decisions / synapses。
- 沙盘总控页已显示 `主循环事件流` 面板，能看到最近跨模块状态变化。
- 沙盘总控页的 `启蒙收件箱` 已接入真实 pending 计数；有候选时会直接显示还剩多少条等待确认入宫。
- 新增事件账本 localStorage fallback 单测；启蒙归档相关测试已同步通过。
- 已通过 `npm run verify`。

## Iteration 4: 启蒙到知识库的自动编译闭环

目标评分提升：知识/记忆 7.0 -> 8.5，产品闭环 7.8 -> 8.4。

交付：

- 启蒙收件箱支持批量确认后的自动 materialize/compile。
- 每条启蒙记忆能看到原文、归类、进入了哪个 wiki page、被哪些回答引用。
- 加去重与冲突提示，避免同一知识重复沉淀。

验收：

- 新确认的一批启蒙内容能在知识问答中被引用。
- Citation 可点击，能回到原始来源和归档路径。

当前执行结果：

- 启蒙候选确认归档时会先创建/复用 `wiki_sources`，再创建 `mempalace_drawers`。
- 新建 drawer 的 `metadata.sourceId` 会指向对应 `wiki_sources.id`，编译器可从 drawer 找回原始来源。
- 归档后的 candidate metadata 会记录 `archivedSourceId` 和 `archivedDrawerId`。
- `wiki-compiler` 分块写入 `wiki_chunks` 时已补上 `source_id`、`drawer_id` 和 `metadata_json.sourceIds/drawerIds`。
- 后续知识问答命中编译 chunk 时，citation 不再只知道 page，而能回到启蒙 source/drawer。
- 已补充启蒙归档测试，覆盖 conversation 与 qimeng-corpus 两条归档路径的 source materialize。
- 启蒙对话气泡确认、收件箱单条确认、收件箱批量确认都会非阻塞写入 `Wiki 编译队列已接收` 事件。
- 编译队列事件记录 candidateIds、drawerIds、sourceIds，并进入沙盘总控台 `主循环事件流`，让归档不再停在“已确认”状态。
- `wiki-compiler` 已在编译启动、空队列巡检、完成/部分完成/失败时回写 `agent_action`，归档后的知识编译状态能继续被沙盘追踪。
- 已补充编译队列和编译器事件 localStorage fallback 单测，防止浏览器开发模式下丢失这条闭环状态。

## Iteration 5: Boss 画像作为全系统上下文

目标评分提升：愿景贴合 8.3 -> 9.0，Agent 复用 7.8 -> 8.6。

交付：

- 画像工坊输出不只是一份报告，而是可版本化的 `BossCognitiveProfile`。
- Openbasaka、WarRoom、Teams、Knowledge Query、Telegram bot 都注入同一份画像摘要。
- 每次画像变化显示“影响了哪些 Agent 行为”。

验收：

- 同一个问题在不同 Agent 中保持一致的 Boss 理解。
- 新画像版本能回滚、比较、解释差异。

当前执行结果：

- Boss 认知画像已经通过 `cognitive_profile_json` 持久化，并由 `renderCognitivePrompt()` 输出统一上下文。
- Openbasaka、Knowledge Query、Teams、小白诊断此前已接入同一份认知画像。
- 本轮补齐 WarRoom 推演：竞品分析师、挑剔用户、冷酷投资人与最终存活率汇总都会接收 Boss 认知操作系统提示。
- 本轮补齐 Telegram Bot：Telegram 对话会读取 `cognitive_profile_json`，把 Boss 的使命、讲解偏好、理解路径和禁区注入 `<boss-profile>`。
- 手动编辑认知画像或画像工坊应用新画像时，会写入 `boss_signal` 事件，并标注影响入口：Openbasaka、Knowledge Query、Teams、WarRoom、Telegram Bot、XiaoBai Diagnose。
- Boss 项目匹配评分已增强中文禁区匹配，类似“纯流量生意”这类偏好红线能命中“流量套利/流量打法”等项目文本。
- 已补充 Boss cognition impact 单测，防止画像更新后不再进入主循环事件流。

## Iteration 6: 推演室从报告变为行动系统

目标评分提升：产品闭环 8.4 -> 9.0，愿景贴合 9.0 -> 9.2。

交付：

- 推演结果拆成假设、风险、行动、观察指标、复盘时间。
- 一键生成 Agent 任务、Cron 提醒、知识检索任务。
- 行动完成后回写项目状态和 Boss 偏好。

验收：

- 一次推演至少生成一个可执行任务，并能在沙盘追踪状态。
- 复盘能反向更新项目评分和 Boss 模型。

当前执行结果：

- 新增 WarRoom action plan 模块，把项目推演结果拆成 `hypotheses`、`risks`、`actions`、`metrics`、`reviewAt`。
- 推演室新增 `推演行动计划` 面板，选中项目后直接显示假设、风险、行动、观察指标与复盘日期。
- `生成 Agent/Cron 任务` 会把行动计划 materialize 到 Scheduler：策略拆解、失败预演、市场/知识证据检索、复盘任务。
- 行动计划会写入 `project_signal`，每个行动会写入 `agent_action`，沙盘总控台能继续追踪“推演 -> 执行”的状态。
- Scheduler 类型补上 `agent-task`，让 WarRoom 生成的执行任务能使用完整 Agent 栈。
- Cron/Scheduler 执行器已接入任务结果回写：任务成功或失败都会生成 `agent_action` 复盘事件。
- WarRoom 关联项目的任务完成后会额外沉淀 `boss_memory` insight，失败时也会以较低置信度记录阻塞信号，方便下一次推演反向学习。
- 新增任务结果回写单测，覆盖 WarRoom 项目任务与普通任务两条路径。

## Iteration 7: Agent 团队与工具执行可信化

目标评分提升：Agent 复用 8.6 -> 9.2，稳定性 6.5 -> 8.0。

交付：

- Agent 任务有输入、工具调用、结果、引用、成本、失败恢复。
- MCP/工具权限分层，危险命令必须明确标注。
- Agent 记忆回写启蒙/知识库，而不是只停留在聊天历史。

验收：

- 任意 Agent 输出都可追踪证据链。
- 失败任务能重试或转人工确认。

当前执行结果：

- 新增 `AgentExecutionReceipt`，把 Agent/Cron 执行的输入摘要、输出摘要、工具引用、证据引用、成本估算、重试建议和风险等级结构化。
- Cron/Scheduler 任务结果回写时会把 receipt 写入 `agent_action.payload_json`，沙盘事件流不再只有一段结果文本。
- 新增工具信任审计层：`executeTool()` 每次调用都会写入 `agent_action` 工具事件，包含工具 tier、风险等级、输入摘要、结果摘要和失败重试建议。
- `terminal` 工具已接入 `command-guard`，危险命令会被拒绝，并以高风险失败收据进入主循环账本。
- 沙盘总控台新增 `执行收据` 面板，直接展示最近 Agent/工具执行的风险等级、输出摘要和下一步复盘出口。
- 新增通用 `execution-audit` 写入器，团队 Agent 与 Tool Loop 不再绕过执行收据层。
- `runToolLoop()` 的 skill/MCP 调用会写入 `tool-loop` 收据，记录技能 ID、MCP server、结果和失败重试建议。
- `runTeamSession()` 的 permanent/agency/brainstorm 三种团队模式都会为每个 Agent 回复写入执行收据，并标记知识上下文与 Boss 认知画像引用。
- Openbasaka 普通对话与工具调用已接入 `execution-audit`，普通回复、工具后回复、工具失败都会进入执行收据。
- XiaoBai 诊断、知识命中、原始记忆命中、实时搜索生成和追问都会写入执行收据。
- Telegram Agent 主进程侧已直接写入 `operating_events`，普通对话、`/ask`、`/search` 与失败处理都会留下同结构 receipt。
- 已补充执行收据与工具信任审计单测。

## Iteration 8: 执行复盘学习层

目标评分提升：产品闭环 8.6 -> 9.1，Agent 可复用性 8.6 -> 9.2。

交付：

- 把 `AgentExecutionReceipt` 转成可评分、可排序、可导航的复盘队列。
- 为每次执行计算可信分、证据覆盖、风险优先级、重试/沉淀/补证据建议。
- 沙盘总控台展示“执行学习”指标和“复盘学习”面板，让执行层不再只是日志。

验收：

- 失败、重试、高风险、缺少证据、可沉淀五类执行结果能被区分。
- 最近 Agent 行为能直接导向控制面板、知识库、记忆宫殿、Scheduler 或团队 Agent。

当前执行结果：

- 新增 `execution-review` 学习层，支持从 `operating_events` 解析 receipt 并生成 `AgentExecutionReview`。
- 可信分会综合状态、工具失败、风险等级、重试建议、证据覆盖和输出可读性。
- 沙盘总控台新增 `执行学习` 指标，展示平均可信分、需重试数量和证据覆盖率。
- 沙盘总控台新增 `复盘学习` 面板，优先暴露需要介入、需要复盘、可沉淀和观察中的执行记录。
- 已补充复盘学习单测，覆盖高可信沉淀、失败介入、无证据复盘三条路径。

## Iteration 10: 产品体验 polish

目标评分提升：信息架构 8.0 -> 9.2，产品闭环 9.0 -> 9.3。

交付：

- 统一视觉层级、空态、加载态、错误态、长任务进度。
- 对 Boss 使用“可内化”的呈现：结论、证据、下一步、可点击来源。

验收：

- 长任务不会静默空白。

验收：

当前执行结果：
