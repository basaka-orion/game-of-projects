# 《启蒙》史诗工程总蓝图

更新时间：2026-04-22

## 0. 定义

《启蒙》不是普通资料夹。

它是你过去 10 年关于“自身如何理解世界、如何探索世界、如何与世界发生作用”的长期记录总入口，也是 Openbasaka 后续一切长期记忆、认知递进、项目演化的第一性资产。

本工程的首要目标不是“把 6000 多篇内容搬进系统”，而是先确立一套可长期迭代、可验证、可追溯、可点击归档的稳定契约，然后再开始规模化入宫。

## 1. 稳定核心契约

截至 2026-04-22，`MemPalace/mempalace` 的 README、概念页、参考页之间存在若干口径差异，例如：

- `room` 在不同页面里既被描述为“主题单元”，也被描述为“时间单元”
- MCP 工具数出现过 `19` 和 `29` 两种说法
- `agents` 页与 README 对 `mempalace_list_agents` 的表述并不完全一致

因此，本工程不直接照搬宣传文案，而锁定以下稳定核心：

1. `verbatim first`
   原文逐字保存是默认路径。任何总结、Wiki、AAAK、洞察都只能建立在原文之上，不能替代原文。
2. `wing / room / hall / drawer`
   记忆必须有可导航层级，且层级是查询、回忆、交叉联想的一部分，不是装饰。
3. `L0-L3 memory stack`
   系统必须具备身份层、关键故事层、按需召回层、深度搜索层，而不是每次都把全量记忆塞进 prompt。
4. `search before speak`
   只要涉及过去的你、过去的项目、过去的决策、过去的认知，系统应先查再答。
5. `local first`
   《启蒙》是你的底层认知资产，必须以本地优先、可导出、可恢复、可追溯为前提。

## 2. 三架齿轮

这项工程的真正主循环不是单一知识库，而是三架齿轮持续互相推进：

1. 《启蒙》
   你的十年认知、探索、反思、愿望、未完成项目、关键转折的长期语料底座。
2. 画像工坊
   你提到“最终的全部测试”是探索与认知世界的指导方向，因此它不是旁支，而是《启蒙》的导航仪与优先级校准器。
3. Openbasaka 创意/项目/对话系统
   这是你实际探索世界的方法层。你生成的创意、项目、对话，不是附属品，而是新记忆与新方法的发生器。

闭环如下：

`《启蒙》提供底层世界模型 → 画像工坊校准当前阶段方向 → Openbasaka 产出新的创意/项目/对话 → 被点击归档后重新进入《启蒙》 → 再次反哺画像与行动`

## 3. 《启蒙》分类法 V1

### 3.1 顶层命名

- 文件夹正式名称：`启蒙`
- 展示名称：`《启蒙》`
- 系统角色：Openbasaka 的“长期认知根目录”

说明：

- 文件系统层使用 `启蒙`，避免在路径里引入书名号
- UI 与文档层统一展示为 `《启蒙》`

### 3.2 Wing 规则

本工程将 `wing` 固定为“高阶认知领域”，而不是混杂使用。

| Wing ID | 中文名称 | 存放内容 |
| --- | --- | --- |
| `identity` | 自我定义 | 核心信念、价值观、人格底色、长期偏好、自我叙事 |
| `worldview` | 世界模型 | 对社会、文明、科技、关系、系统、时代的理解 |
| `method` | 探索方法 | 学习法、思考法、认知工具、决策法、创作法 |
| `creation` | 创意与项目 | 项目构想、作品设想、原型方向、实验提案 |
| `dialogue` | 关键对话 | 与人、与 AI、与自己的关键问答、对撞、转折性会话 |
| `profiling` | 画像工坊 | 测评结果、画像变化、阶段信号、指导方向 |
| `wishes` | 未竟心愿 | 长期想做却尚未完成的愿望、召唤、执念、未来线索 |
| `openbasaka` | 系统演化 | 对个人智能系统、记忆宫殿、代理协作方式的设计与迭代 |

### 3.3 Room 规则

`room` 固定为“可命名主题束”，可来自：

- 一个具体项目
- 一个持续问题
- 一个思想主题
- 一个阶段性线程
- 一个重要人物/关系线

示例：

- `room = ai-文明判断`
- `room = 画像工坊-最终测试`
- `room = 项目-记忆宫殿系统`
- `room = 关系-亲密与协同`
- `room = 方法-长期主义`

约束：

- `room` 优先表达“主题”，不是表达“文件格式”
- 当一批内容同时具备时间性与主题性时，时间写入元数据，主题写入 `room`

### 3.4 Hall 规则

为兼容 MemPalace 当前更稳定的内容类型路由思路，`hall` 采用内容类型，而非时间维度：

| Hall ID | 用途 |
| --- | --- |
| `identity` | 自我认识、价值观、自我校准 |
| `consciousness` | 哲学、存在、世界观、元认知 |
| `creative` | 创意、项目灵感、混种构想、表达冲动 |
| `technical` | 系统设计、工程方案、方法框架、结构化知识 |
| `memory` | 经历、事件、里程碑、具体回忆 |
| `emotions` | 情绪、痛苦、渴望、恐惧、心愿触发点 |
| `family` | 亲密关系、重要人物、关系结构、家庭语义 |

### 3.5 Facet 规则

由于官方文档在 `hall` 定义上存在差异，本工程额外引入 `metadata.facets`，用于表达叙事功能：

- `fact`
- `event`
- `discovery`
- `preference`
- `advice`
- `decision`
- `question`
- `wish`
- `pivot`

结论：

- `hall` 负责“这段内容是什么类型”
- `facet` 负责“这段内容在叙事里扮演什么角色”

## 4. 点击式归档门

这是本工程最关键的产品规则之一。

### 4.1 总原则

在 Openbasaka 中，所有创作、创意、对话、洞察，都只生成“归档候选”，不直接自动写入《启蒙》。

只有当你点击那个优雅、自然、可点击的标签后，它才会被正式归入记忆宫殿。

### 4.2 UI 契约

每条候选内容旁都应生成一个自然标签，格式类似：

- `✦ 归入启蒙 · identity / 核心信念`
- `✦ 归入启蒙 · creation / creative / 项目-记忆宫殿系统`
- `✦ 归入启蒙 · worldview / consciousness`

点击后应进入一个极轻量确认层，展示：

- 建议归档位置：`wing / hall / room`
- 归档理由：为什么系统认为它值得入宫
- 去重风险：是否与已有 drawer 高相似
- 来源指针：来自哪段对话/哪条创作/哪个测试
- 可改字段：标题、room、tags、facet

### 4.3 行为规则

1. 不点击
   仅保留在当前会话或临时工作区，不进入长期记忆。
2. 点击确认
   写入 verbatim drawer，并生成完整 metadata。
3. 点击后修改
   允许修正目标 `wing / room / hall / facet / tags`，防止系统替你误分。
4. 自动学习改为候选生成
   `self-nudge`、`convo-miner`、`forge` 未来应从“自动落库”调整为“生成候选 + 等待确认”。

## 5. 工程阶段

### Phase 0：命名与契约冻结

交付物：

- 《启蒙》命名确定
- MemPalace 稳定核心契约确定
- 三架齿轮主循环写入仓库文档
- MCP / skills 能力矩阵冻结

### Phase 1：Verbatim 迁移底座

交付物：

- 将 6000+ 内容按《启蒙》根目录纳入 ingest 范围
- 批量生成 drawers
- 建立 dedupe、source pointer、folder scope、导入日志
- 明确哪些内容来自外部文件，哪些来自系统对话

### Phase 2：分类与编译闭环

交付物：

- `wing / room / hall / facet` 分类器
- drawer -> wiki 编译流水线
- 关键双链、索引页、反向引用
- 画像工坊结果与《启蒙》优先级联动

### Phase 3：点击式归档门

交付物：

- Openbasaka 对话区候选标签
- 创作区候选标签
- 画像工坊结果归档候选
- 归档预览面板
- 去重校验与撤回机制

### Phase 4：回忆与导航升级

交付物：

- L0-L3 记忆栈真正落地
- 面向《启蒙》的 wing/room scoped wake-up
- 项目、画像、关系、世界观的跨翼隧道
- 关键知识的矛盾检测与时间有效性管理

### Phase 5：自动化与代理协作

交付物：

- 专门整理《启蒙》的 agent diary
- 定时编译、定时校对、定时反思
- 以画像工坊结果驱动的“最近应重点沉淀什么”
- 以项目推进驱动的“哪些内容必须回写《启蒙》”

## 6. 不可妥协的红线

1. 不允许用总结覆盖原文
2. 不允许把“点击归档”降级为默认自动归档
3. 不允许把《启蒙》做成纯向量黑箱，必须保留可走入的结构
4. 不允许知识层与记忆层断链，任何 Wiki 都必须能回溯 drawer
5. 不允许画像工坊成为孤岛，它必须参与优先级排序
6. 不允许 Openbasaka 创意系统与《启蒙》脱钩，它本身就是探索方式的一部分

## 7. 立即开工顺序

下一步建议严格按这个顺序执行：

1. 先把《启蒙》根目录、分类法、MCP/skills 配置准备好
2. 再做“点击式归档门”的产品与数据契约
3. 再批量迁移 6000+ 内容进入 drawers
4. 然后才启动大规模编译与 UI 深化

这是为了避免一开始就把十年认知资产错误写入、错误分类、错误压缩。
